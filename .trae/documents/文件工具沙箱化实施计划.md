# 文件工具沙箱化实施计划

> 唯一实施依据。承接 L1（run_command / process_start 已沙箱化，见 `L1-OS沙箱实施计划.md`）。
> 文档名不带 L2 前缀：此前口头说的「L2」指 seccomp / deny default 收紧，与本计划不同事。

## Context

用户拍板：**五个文件工具（read_file / write_file / list_directory / glob_search / grep_search）必须全部改为经 `mino-sandbox` sidecar 在 OS 沙箱内执行**，推翻此前「文件工具留进程内走权限模型」的分层设计。

动机与收益：
- 现状 `resolveWorkspacePath`（tools.ts:340-347）只做字符串前缀判断，**工作区内的符号链接可逃逸到工作区外写入**——OS 沙箱硬性 containment 直接封死该漏洞。
- 写入范围由 OS 保证而非仅靠确认流程：断网、系统目录只读、可写目录白名单。
- 读/搜索工具同样进沙箱（ro 档全盘禁写），实现完整的纵深防御。

### 拍板决策（用户跳过提问，按「必须」最严格合理解读执行，评审时可否决）

| 决策点 | 取值 |
|---|---|
| full 级写入范围 | **home 档**：工作区 ∪ $HOME ∪ tmp 可写，系统目录永远只读 |
| workspace / readonly 级 | 区内写 **ws 档**（工作区 ∪ tmp）；区外写经确认后升级 **home 档**（保留现有能力矩阵） |
| 沙箱不可用时 | **一律硬失败**：五工具拒绝执行 + 原因 + 修复提示（与 run_command 的回退语义**刻意不同**） |
| 工具范围 | 五个全进；**globby 弃用**，glob 统一用已捆绑的 rg（@vscode/ripgrep） |

权限确认流程（needsConfirm + humanInTheLoopMiddleware + GATED_FILE_TOOLS=write_file）**不变**，只换底层执行。

### 平台技术选型（2026-11-16 用户拍板）

| 平台 | 文件系统视图 / 隔离 | 写入强制 |
|---|---|---|
| Linux | **bubblewrap (bwrap)**：创建 mount namespace，根目录以 `--ro-bind / /` 只读挂载，仅白名单目录 `--bind` 可写，提供隔离的文件系统视图 | **Landlock（内核 LSM）作为第二道防线**：sidecar 在沙箱内自 exec 的内层进程上启用，内核层面强制限制文件写入——即使 bwrap 配置失误，写白名单之外的路径仍被内核拒绝 |
| macOS | **Seatbelt**（系统自带，经 `sandbox-exec`）：编写 Sandbox Profile 限制文件写入（`(deny file-write*)` + 白名单 subpath 放行），系统级强制 | —（单层即内核强制） |
| Windows | AppContainer（token 级隔离 + 0 capability 断网） | **ACL Runner**：文件权限完全由 DACL/ACL 管控——按 scope 对容器 SID 授予工作区 F / HOME RX / HOME F，白名单外的写被内核 ACL 拒绝 |

Linux 双层关系：bwrap 管**视图**（namespace、挂载），Landlock 管**访问**（同一 inode 上内核强制，不受挂载视图欺骗）。Landlock 尽力启用：内核不支持（< 5.13 等）时静默跳过，bwrap 主防线仍然有效——第二道防线不可用不拒绝执行。详见「Linux：bwrap + Landlock 组合」小节。

### 范围外（不改动）

web.ts 文件面板 RPC（用户手点、硬限工作区）、config.ts 配置读写、agent.ts SQLite checkpoint、终端功能、run_command / process_start 现有沙箱路径。

## 一、sidecar 协议扩展（sandbox/）

新增**自 exec 双层**子命令（main.go switch）：

```
fs <read|write|list> --cwd <ws> --scope <ro|ws|home> -- <absPath>  # 外层：建沙箱后 exec 自身
_fsread  --scope <s> -- <absPath>                                  # 内层：沙箱内直接 Go IO
_fswrite --scope <s> -- <absPath>
_fslist  --scope <s> -- <absPath>
_exec    --scope <s> -- <argv...>          # 仅 Linux 内层：启用 Landlock 后 exec 目标命令（run/start）
```

- `fs` 外层：`parseFsArgs` 解析参数（scope 必填）；stat(cwd) 非 dir → unavailable；用 `os.Executable()` 拿自身路径，构造 argv `[self, "_"+sub, "--scope", scope, "--", target]`，复用平台 wrapper + runAndWait 跑在沙箱内。read/list 的 scope 恒 `ro`，write 按权限映射。
- 内层 `_fs*`（新文件 **sandbox/fs.go**，无构建标签，三平台共用）：
  - `_fsread`：`os.ReadFile` → stdout 原样字节
  - `_fswrite`：`io.ReadAll(os.Stdin)` → `os.MkdirAll(dir, 0755)` → `os.WriteFile(path, data, 0644)`（对齐现有 mkdirSync recursive 行为）
  - `_fslist`：`os.ReadDir` → stdout JSON `[{name, type:"dir|file|other", size?}]`（size 仅文件且 Info() 成功时给——对齐现有 stat 失败静默）
  - 错误一律 stderr 首行 + exit 1
  - Linux 上 `_fs*` 启动时先按 scope 启用 Landlock（见下节），再做 IO
- stdin 链路：Node spawn 外层 → runAndWait 透传 os.Stdin → 沙箱内 `_fswrite` 读 stdin。write 内容走这条路。

**parseRunArgs（main.go:68）扩展**：`--scope` 可选、默认 `"ws"`（run/start 现语义零变化）；`--ro <path>` 可重复（仅 Windows 消费：额外 RX 授权，用于 rg 二进制目录、grep 单文件目标）。

**scope 三档语义**（平台后端各自落地；Linux 每档均为 bwrap + Landlock 双层，白名单两处一致）：

| 档 | Linux bwrap 绑定 + Landlock 写白名单 | macOS Seatbelt | Windows AppContainer + ACL Runner |
|---|---|---|---|
| ro | 不 `--bind` 工作区（ro-bind / 已可读，全盘禁写）；Landlock 白名单 ∅ | 仅放行 /private/tmp、/tmp | cwd 授 RX（无 F） |
| ws | `--bind cwd cwd`（现行为）；Landlock 白名单 {cwd, /tmp} | + 工作区双路径 | cwd 授 F（现行为） |
| home | **先 `--bind $HOME $HOME` 再 `--bind cwd cwd`**（恒含工作区）；Landlock 白名单 {cwd, $HOME, /tmp} | + HOME 双路径 + 工作区双路径 | cwd F + %USERPROFILE% F |

**关键修正（评审时定案）**：home 档必须恒包含工作区绑定——否则 full 级写不在 $HOME 下的工作区（如 /srv/ws）会被误拒。三平台 home 档 = 工作区 ∪ $HOME ∪ tmp。

### Linux：bwrap + Landlock 组合（新增 Landlock 层）

进程链（run/start/fs 三类统一经内层自 exec）：

```
宿主 Node → sidecar 外层（构造 bwrap argv、建沙箱）
  └─ bwrap（mount namespace：/ 只读 bind、白名单 --bind 可写、私有 /tmp）
      └─ sidecar 内层（bwrap exec `self _exec/--fs*`）
          ├─ 按 scope 启用 Landlock（prctl → create_ruleset → add_rule → restrict_self）
          └─ syscall.Exec 目标命令 / 执行 Go IO（pid 不变，stdio / Setpgid / 组杀语义不变）
```

- **必须在内层（bwrap 之后）启用**：Landlock 规则按 inode 生效，沙箱内 /tmp 是私有 tmpfs（与宿主 /tmp 不同 inode），外层启用会把沙箱内 /tmp 误判为白名单外
- **白名单映射**：ro=∅、ws={cwd, /tmp}、home={cwd, $HOME, /tmp}——与 bwrap bind 集合同源，同一 scope 语义双保险
- **实现**：`golang.org/x/sys/unix` v0.30.0 只收录 Landlock 常量与 syscall 号、无函数封装，手工 `unix.Syscall(SYS_LANDLOCK_CREATE_RULESET/…_ADD_RULE/…_RESTRICT_SELF)` 调用；create 的 size 固定 8（只声明 Access_fs 字段——老内核不 E2BIG，新内核把 net/scoped 字段视为不 handled）
- **handled 集合（实施修正，2026-11-16）**：取**全部写类 rights**（WRITE_FILE、REMOVE_DIR/FILE、MAKE_CHAR/DIR/REG/SOCK/FIFO/BLOCK/SYM），刻意不含读类（EXECUTE/READ_FILE/READ_DIR——全盘读不进 Landlock 管控面）；按探测 ABI 追加 REFER（v2/5.19）、TRUNCATE（v3/6.2）。原稿 {WRITE_FILE, TRUNCATE, REFER} 不够：Landlock 只管 handled 的 rights，不含 MAKE_REG/REMOVE_FILE 时 mkdir/rm/建文件全绕过，第二道防线名不副实
- **ABI 探测（替代原稿的 EINVAL 逐级缩减）**：`landlock_create_ruleset(NULL, 0, LANDLOCK_CREATE_RULESET_VERSION)` 直接返回内核 ABI 版本，按版本组装 handled/放行集合，无需试错重试；ENOSYS（内核 < 5.13）/EOPNOTSUPP（LSM 未启用）→ 静默跳过
- **降级语义刻意宽松**：Landlock 不可用绝不判沙箱不可用、不拒绝执行——bwrap 主防线仍完整；Landlock 是纵深加固，不是可用性前提
- **run/start 改道**：Linux 平台 wrapper 原本 bwrap 直接 exec 用户命令，改为 exec `[self, "_exec", "--scope", s, "--", ...argv]`，内层启用 Landlock 后 `syscall.Exec` 目标——进程映像替换 pid 不变，L1 的进程组、SIGTERM 组杀、孤儿兜底、退出码透传语义零变化。macOS/Windows 的 run/start 不套 `_exec`（无第二道防线，维持 L1 直 exec）
  - **实施注记（2026-11-16）**：改道点在 main.go 协议层（run/start case 统一调 `execArgv`，`_exec` case 分发到 `execInner`），不在 linux.go 的 sandboxRun 内部包——fs 外层也调 sandboxRun 且自带 `_fs*` 内层 argv，包一层会重复改道。`syscall.Exec` 不查 PATH（bwrap 是 execvp 语义），内层先 `exec.LookPath(argv[0])` 解析绝对路径。exec 失败对齐 shell 的 127 惯例而非 unavailable(125)——argv[0] 起不来是目标命令的问题，不触发 Node 侧「沙箱不可用回退宿主」。probe 不变（Landlock 非可用性前提）

**平台后端签名统一改**：`sandboxRun(cwd, scope string, roDirs []string, argv []string)`（linux.go:65 / windows.go:344 / darwin.go:92）。HOME 取 `os.Getenv("HOME")`，空/不存在 → unavailable。

**Windows 细节（ACL Runner，prepareSandbox, windows.go:140）**：AppContainer 提供隔离 token 与断网，文件读写权限全部由 DACL 授权管控：
- home RX 授权恒做（读语义，现行为）
- fs 路径额外授权：sidecar 自身所在目录 RX（AppContainer 内自 exec 需要）、target 本体（read→文件 RX / list→目录 RX / write→不授权，靠 scope containment）
- roDirs 逐个 RX

## 二、Node 侧改造（src/tools.ts）

1. **isSandboxAvailable（tools.ts:88）**：缓存改 `{ok, reason}`——spawn error→「sidecar 缺失，请先 npm run build:sandbox」、超时→「探测超时」、非 0→剥 marker 取原因。run_command/process_start 仅判 `.ok`，回退语义不变。
2. **runShellCommand（tools.ts:111）**加 `opts?: {stdin?: string; cap?: number}`：stdin 走 pipe+end（EPIPE 静默）；输出改 **Buffer 聚合、cap 按字节、结束时统一 toString**（修复多字节字符跨 chunk 被替换为 U+FFFD 的隐患，run_command 同样受益）。
3. **runInSandbox（tools.ts:152）**加 `scope`、`roDirs` 参数，argv 前插 `--scope` / `--ro`。
4. **新 helper**：
   - `ensureSandbox(): Promise<string|null>`——null=可用；否则硬失败文案「OS 沙箱不可用（原因）。文件工具仅在沙箱内执行，已拒绝操作。修复：npm run build:sandbox；Linux 需安装 bubblewrap」

5. **五工具改造**（`createFileTools(workspace)` 加 permission 形参，createTools → agent.ts:169 调用点同步传参）：
   - **read_file**：ensureSandbox → `runFsOp("read", ws, "ro", target, cap=1_000_000)` → code≠0 时 `读取失败：<stderr首行>`；>20000 字符截断与「(空文件)」文案不变（Node 侧）。
   - **write_file**：`scope = full ? "home" : inside ? "ws" : "home"`（能执行到区外写说明已被中间件确认）；stdin=content；成功文案「已写入 …（N 字符）」不变（Node 计数）。
   - **list_directory**：`runFsOp("list", ws, "ro", target)` → JSON.parse → Node 格式化现有文案；空数组→「(空目录)」。
   - **glob_search**：**删 globby**。经 `run --scope ro --cwd <根>` 跑捆绑 rg：
     - 参数：`--files --hidden --no-ignore`（globby 不尊重 gitignore，需对齐）+ `-g <pattern>` + `-g '!**/{17个噪声目录逗号串}/**'`（大括号一次排除，已实证后序优先）
     - **根层锚定翻译（已实证）**：pattern 含 `**` → 原样；否则 `--max-depth <(pattern 中 '/' 数)+1>`（无 `/` 即 1，等价 expandDirectories:false；`-g './*.ts'` 实测无效不可用）
     - rg 无匹配 exit 1 → 视为空列表非错误
     - 早停 201 行后 kill；文案改「匹配超过 200 个，仅显示前 200 个」（精确计数不再可得）；`.sort()` 与错误文案不变
   - **grep_search**：rg 参数拼接（tools.ts:559-576）**完全不变**；`runRipgrep`（tools.ts:377）只换 spawn 目标为 `runInSandbox(scope "ro")`：目录模式 `--cwd <根>`；单文件模式 `--cwd <workspace>` + `--ro <absFile>`（Windows 读取授权）。**保留现有流式收集 + 满 50 行早停 kill**（sidecar 透传 stdio，SIGTERM→组杀 L1 已实测可靠），行为逐字不变；rg 无全局 max-count（`-m` 仅 per-file），早停也规避了大输出 200K 缓冲问题。
6. 前置 existsSync/statSync 目录检查保留（仅元数据，不改语义）。

## 四、已知限制与风险（写入交付说明）

1. **Linux Landlock 尽力启用**：内核 < 5.13（或容器环境屏蔽 Landlock）时第二道防线缺席，bwrap 主防线仍完整；Landlock 拦截与 bwrap 只读挂载的报错都表现为写入失败（EROFS / EACCES），失败原因无法从错误码区分是哪一层拦的（对语义无影响）。
2. **沙箱内 /tmp、/dev、/proc 为私有实例**（沿袭 L1 run_command 语义）：read_file / glob / grep 访问宿主 /tmp（及 /dev、/proc 被覆盖位）下的文件会报不存在——ro-bind / / 全盘可读不含这三个被 tmpfs/dev/proc 覆盖的位置；Windows 的 TEMP 同理为容器私有目录。CLI 已实测确认。
3. **Windows 读取范围**：HOME 外文件靠 fs 路径对 target 逐次 RX 授权兜住；rg 搜索 HOME 外目录靠 cwd RX；关闭继承的子目录仍读不到（沿袭 L1）。
4. **Windows ACL 持久化**：home 档给 %USERPROFILE% (OI)(CI)F 永久驻留；每次 fs 调用 2-3 次 DACL 写（幂等合并不堆积）。
5. **确认后的写入仍受限**：workspace/readonly 确认后的区外写被 home 档限制在 HOME+tmp（/etc 等即使确认也拒）——拍板的刻意行为。
6. **rg/globby 细微差异**：超大匹配计数从精确值变「超过 200 个」；`--no-ignore` 下 rg 会多列被 gitignore 的文件（=globby 现状）；Windows 路径分隔符 `\`（与 grep 现状一致）。
7. **性能**：每文件操作 spawn 一次 bwrap/sandbox-exec + 自 exec（Linux 实测量级 10-30ms/次）；grep/glob 早停仍省资源。
8. **read 超大文件**：cap 1M 字符，超出时「全文共 N 字符」的 N 不准（极端场景）。
9. **错误文案**：Go 错误格式（`open /x: no such file...`）替换 Node fs 错误字面，语义等价。
10. **macOS**：编译级验证、待真机（沿袭 L1）；(allow default) 读取全盘与 L1 相同。
11. **Windows 早停 kill**：依赖 L1 已有的终止机制（若 Windows 树杀有缺口属 L1 遗留，非本计划引入）。
